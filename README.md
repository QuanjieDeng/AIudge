# AIudge —— AI 代码审核后台

对每日代码提交做自动化复审（AI + lint），并支持人工标注、协作、统计的闭环系统。
需求见 [doc/需求.md](doc/需求.md)。

多仓库多项目：仓库配置、子系统归类、审核规范、路径过滤全部按仓库隔离，
同一套系统可以同时服务多个项目。语言目前只有 Go 有完整的 AST 级能力（见「已知边界」）。

## 快速开始

```bash
go build -o aiudge ./cmd/aiudge
./aiudge
# 打开 http://127.0.0.1:8787
```

首次启动自动创建内置管理员 **admin / 123456**。默认口令写死在代码里，而它有权读源码、
发群消息，**建议登录后就去右上角改掉**——改不改都不拦着用别的功能。

## 用户与权限

三层角色：

| 角色 | 范围 | 能做什么 |
|---|---|---|
| 全局管理员 | 全平台 | 建/删项目、任命项目管理员、模型网关、全局通知、通知 Prompt、用户管理 |
| 项目管理员 | 单个项目 | 本项目仓库增删改、子系统规则、本项目成员增删（候选人来自项目自己的名单，不是全局用户表） |
| 成员 | 单个项目 | 看本项目的报告与问题、标注、评论、指派 |

**数据按项目隔离**：用户只能看到自己参与的项目下的仓库、问题、报告、统计。
所有列表接口都带项目过滤，按 id 直取的详情接口单独校验归属。

登录方式：
- **普通用户走飞书扫码**（§4.7 的 @ 通知依赖飞书 open_id，走密码的人收不到）
- **管理员可用账号密码兜底**（飞书没配或临时挂了时还能进后台）

新增用户后，由**全局管理员**在「设置 → 用户」里看到；
再在「项目 → 成员」里把人加进对应项目，否则他登录后什么都看不到。

单二进制，无外部中间件：SQLite 用纯 Go 驱动（无 cgo），前端 `go:embed` 内嵌，无需 npm。

## 配置

**配置只从文件读，不看环境变量。** 首次启动自动生成 `aiudge.conf` 模板（所有项都是注释状态），
把需要的打开填上即可：

```ini
AIUDGE_ADDR=:8787
AIUDGE_BASE_URL=http://127.0.0.1:8787
AIUDGE_FEISHU_APP_ID=cli_xxxxxxxx
AIUDGE_FEISHU_APP_SECRET=xxxxxxxx
```

配置文件路径用 `-config` 指定，默认 `./aiudge.conf`：

```bash
go run ./cmd/aiudge -config ./conf/aiudge.conf
```

- 显式指定的文件不存在 → **直接报错退出**，不默默用默认值跑起来
- 默认路径不存在 → 生成模板，按默认值启动
- 文件里含密钥 → 自动 chmod 600 并在日志里警告

### 两类配置项

| | 来源 | 说明 |
|---|---|---|
| **启动参数** | 只认配置文件 | 监听地址、数据目录、并发、超时、飞书应用凭据、规范文档白名单 |
| **界面可改项** | 配置文件是**初始值**，界面改过就以界面为准 | 模型网关、全局通知 webhook、每日汇总时间 |

界面可改项在界面上存库，所以优先级是：

```
内置默认值  <  配置文件  <  界面上的设置
```

两边都填了不同值时，启动日志会点出来，免得对着「配置文件改了没生效」查半天：

```
以下项在配置文件 ./aiudge.conf 里填了，但已被界面上的设置覆盖:
模型网关地址（界面: http://ui-gateway:4000）。以界面为准；想改回配置文件，先去界面上清掉
```

界面上也会标明当前值来自哪儿（「设置 → 模型配置」和「设置 → 通知」里的来源标签）。

### 全部配置项

| 键 | 默认值 | 说明 |
|---|---|---|
| `AIUDGE_ADDR` | `:8787` | 监听地址 |
| `AIUDGE_BASE_URL` | `http://127.0.0.1:8787` | 对外访问地址。决定飞书回调地址和通知里的后台链接 |
| `AIUDGE_DATA_DIR` | `./data` | 数据目录（SQLite、仓库工作副本） |
| `AIUDGE_DB` | `<数据>/aiudge.db` | SQLite 路径 |
| `AIUDGE_WORK_DIR` | `<数据>/repos` | git 浅克隆工作副本 |
| `AIUDGE_SECRET_KEY` | 自动生成到 `<数据>/secret.key` | **64 位 hex 的 32 字节密钥**。**必须固定**，换值等于已有凭据全部作废 |
| `AIUDGE_GATEWAY_URL` | — | LiteLLM 网关地址（界面可改） |
| `AIUDGE_GATEWAY_KEY` | — | 网关密钥（界面可改） |
| `AIUDGE_FEISHU_APP_ID` / `_APP_SECRET` | — | 飞书应用凭据，配了才启用扫码登录 |
| `AIUDGE_FEISHU_WEBHOOK` | — | 全局通知 webhook 兜底（界面可改） |
| `AIUDGE_FEISHU_OAUTH_BASE` | `https://open.feishu.cn` | 私有化飞书换自建域名 |
| `AIUDGE_CONCURRENCY` | `2` | 并发审核任务数 |
| `AIUDGE_MAX_RETRY` | `3` | 重试次数。**仅对 5xx / 429 重试**，配置类错误立即失败 |
| `AIUDGE_SOFT_TIMEOUT_MIN` | `10` | 软超时：告警但不终止 |
| `AIUDGE_HARD_TIMEOUT_MIN` | `30` | 硬超时：终止并标记失败 |
| `AIUDGE_LINT_BIN` | `golangci-lint` | lint 可执行文件 |
| `AIUDGE_LINT_TIMEOUT_MIN` | `5` | lint 超时 |
| `AIUDGE_SUMMARY_CRON` | `30 18 * * *` | 每日汇总时间（界面可改） |
| `AIUDGE_SPEC_DIRS` | 空 | 规范文档的绝对路径白名单。推荐用仓库内相对路径，不用配这个 |

## 接仓库

0. **项目 → 新建项目**（全局管理员），然后在项目里「新增仓库」并添加成员。
1. **设置 → 模型配置**：填 LiteLLM 网关地址与密钥，「从网关拉取」模型列表，设默认模型。
   按仓库单独指定的模型优先于这里的默认值。
2. **仓库 → 新增仓库**：填 Git 地址（只读 token）、分支、语言、路径排除 glob。
   规范文档优先填**仓库内相对路径**（如 `CLAUDE.md`），零配置。
3. **仓库 → 子系统规则**：点「扫描仓库目录，生成候选」，把目录结构和业务名词对上。
   规则只在所属仓库内生效，其他仓库各配各的。
4. **设置 → 身份归并**：把 `dengquanjie1`、`邓全杰` 这类同一人的多个 git 身份绑到一个人；
   CI 机器人勾「机器人」，不计入任何统计。
5. **Webhook**：GitLab 侧填 `http://<host>/api/webhook/<仓库ID>`，
   Secret token 填该仓库的访问凭据（未配凭据则不做校验）。
6. **定时兜底**：仓库配置里填 cron 表达式，只扫过去 24 小时内未被 webhook 覆盖的 commit。
7. **手动触发**：项目设置 → 仓库表格里点「手动触发」，按**提交范围**（下拉选提交，起始那一端不含）
   或**时间范围**（两个本地时间输入框，按提交时间筛）补审一批。提交下拉每次打开都会先同步一次远端，
   同步只 fetch 不动工作副本，所以可以在审核任务正在跑的时候安全地打开；同步失败会退回本地副本的列表
   并如实标出来。一次最多审 30 条，超出的只取最近 30 条。
   这个按钮只给项目管理员和**被授予了「手动触发审核」权限的成员**（项目设置 → 成员管理里勾选）——
   触发一次就是一次真实的模型调用。
8. **通知**：**设置 → 通知** 配全局兜底，**仓库 → 编辑** 配各仓库自己的群。

收件地址三层，从高到低：

```
仓库自己的 webhook  >  界面配置的全局  >  配置文件里的 AIUDGE_FEISHU_WEBHOOK
```

界面能改的排前面，否则「界面上配了却不生效」比不配还难查。

webhook URL 里带着 token（拿到就能往群里发消息），所以和代码凭据同等待遇：
加密存储、界面只回显 `https://…/hook/****1234` 的形态、日志不打印。

通知配错是**静默失败**——配好了但群里没动静，只能翻服务端日志。
所以「设置 → 通知」有个**发送测试消息**按钮，输入框里没保存的地址也能先试。

## 审核 Prompt

**设置 → 审核 Prompt**，可直接编辑发给模型的系统提示骨架。

- **领域细节不要写在这里**——那是每个仓库各自挂载的规范文档的活，写在这儿会强加给所有仓库
- 可用占位符：`{{language}}`、`{{repo}}`
- 点「预览实际发出的内容」看渲染后的结果
- **版本号是内容哈希，自动跟着内容走**。手填的版本必然漂移（改了 prompt 忘改版本号），
  历史曲线就再也解释不清了。改动会在趋势图上留下断点
- 「恢复内置默认」清空自定义。留空时用内置默认，所以升级二进制时默认 prompt 的改进能自动生效

Prompt 模板存在库里（`review_configs` 单行表），任务日志会标出本次用的是内置还是自定义。

## 测试阶段清档

**设置 → 维护 → 清空业务数据**，输入「清空」确认。

只清审核跑出来的数据（问题、任务、报告、评论、审计日志），**仓库配置、模型网关、
用户、身份归并、子系统规则全部保留**，不用重配。清空后编号从 #1 重新开始。

勾「同时删除本地仓库副本」会连 `data/repos` 下的克隆一起删，下次审核重新拉——
大仓库会慢几分钟，但能顺带验证一遍「从零克隆」的路径。

清档会先等正在执行的审核任务收尾再删。不这么做的话，跑了一半的任务会在数据被清空之后
把报告写回来，于是「清空」之后还剩下最后那一条。

也可以直接 `rm -rf data`（会连密钥和克隆一起丢，需要重新配）。

## 架构

```
cmd/aiudge          单二进制入口
internal/store      SQLite 持久层 + 报表聚合（全部 SQL，无 ORM）
internal/gitx       git 浅克隆、commit 区间、unified diff → 改动行号
internal/gocx       改动行 → 所在函数 + 直接调用链（go/ast）；给 AI 的检索工具
internal/lint       golangci-lint 子进程 + JSON 解析，规范/风格类问题全部交给它
internal/llm        LiteLLM 网关瘦客户端（OpenAI 兼容 + 工具调用）
internal/review     审核管线：指纹、prompt、context 组装、问题入库
internal/queue      并发受限的任务队列、指数退避重试、cron 调度
internal/notify     飞书 webhook（格式与 server/base/launch/alarm.go 一致）
internal/auth       飞书 OAuth 登录 + 会话
internal/web        REST API + 报表导出
webui               内嵌前端（原生 JS + 手写 SVG 图表，零构建）
```

### 几个关键设计

- **问题指纹**：`sha256(仓库 + 文件路径 + 分类 + 归一化代码片段)`。行号**不**参与计算——
  插入删除代码会让行号漂移，拿行号当身份会让趋势统计退化成「文件被改频率图」。
  lint 问题额外把 linter 名计入，避免同一行的多个 linter 被折叠成一条。
- **回归检测**：已标记「已修复」或「误报」的问题再次出现时，自动翻回「待处理」并标「回归」。
  这是 AI 生成代码最危险的情形，需要显式信号。
- **审核粒度**：改动行所在函数 + 直接调用链中被调函数的实现（≤60 行的才展开）。
  纯 diff 行看不到函数签名与上下文，整个文件又太贵。
- **跨文件问题**：给 AI 四个检索工具（`grep` / `find_symbol` / `read_file` / `list_dir`），
  按需查代码库。不预建索引——代码每日变动，索引维护成本高。
- **版本标签**：每份报告记录 `模型名 / 模型版本 / prompt版本 / 规范文档版本`。
  规范文档版本是挂载文档的内容哈希，改文档会在趋势图上留下断点。
  否则改 prompt 或换模型前后的曲线不可比，事后无法解释。
- **凭据**：AES-256-GCM 加密落库，界面只回显末四位，日志用 `gitx.Redact` 抹掉 URL 里的 token。

## 已知边界

- **块数据不是历史快照**：报表的处理率/误报率按问题**当前状态**统计，
  不是「在该时间点的状态」。要精确复现历史需拉链表，当前规模（数千条/月）不值得。
- **子系统归类按仓库配置**（规则只在所属仓库内生效），在 Go 侧按路径子串匹配。
  规则改动会立即改变该仓库历史报表的分布口径。
- **目前只有 Go 有完整的 AST 级能力**：`gocx` 用 `go/parser` 定位「改动行所在的函数」，
  `find_symbol` 按 Go 声明语法检索，lint 接的是 golangci-lint。其他语言可以配置，
  但上下文会退化成「改动块±3 行」、`find_symbol` 返回空、lint 跳过——
  单文件问题（安全校验、逻辑边界）照常检出，跨文件问题（重复造轮子、N+1、锁滥用）检出率明显下降。
- **飞书 @ 需要 open_id**：只有走过飞书登录的用户才有，开发登录的用户收不到 @。
- **每日汇总是按仓库分流的**：各自发到各自的群。没配自己 webhook 的仓库会合并成一份
  发到全局兜底 —— 否则多个仓库共用一个群时会收到一串格式雷同、只有仓库名不同的消息。
- 规范文档：**相对路径**在仓库工作副本内解析（推荐，任何项目零配置），
  **绝对路径**必须落在 `AIUDGE_SPEC_DIRS` 白名单下，避免误填路径把无关文件送进模型。

## 测试

```bash
go test ./internal/...
```

覆盖：指纹稳定性与去重边界、回归流转（已修复/误报两条路径）、机器人身份排除、
配置只认文件（环境变量一律不读）与解析容错、

老库迁移（全局规则 → 按仓库）、连接池死锁防护、清档语义（业务数据清光/配置保留）、
prompt 占位符替换（含百分号不被格式动词吃掉）与版本哈希跟随内容、
飞书通知按仓库路由（三层优先级、无配置时静默跳过）、全局通知配置的保存与清空。
